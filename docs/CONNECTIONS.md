# Підключення облікових записів

Dayframe підтримує робочий і особистий Outlook, Календар Google та Slack **лише для читання**. Jira та Confluence вимкнені. Для активації потрібні одноразова реєстрація OAuth-застосунків і твій явний дозвіл під час входу. Автоматичні тести не авторизують реальні облікові записи.

## 1. Розмісти серверну версію

GitHub Pages віддає лише статичні файли й не може виконувати серверний обмін OAuth-токенів. Там працюють особисті завдання та явно позначений деморежим.

Для реальних підключень розмісти репозиторій як вебсервіс Node.js 24 через `render.yaml` або інший хостинг:

- Збірка: `npm ci --no-audit --no-fund && npm run build`.
- Запуск: `npm start`.
- Перевірка стану: `/api/health`.
- На Render адреса визначається через `RENDER_EXTERNAL_URL`. На іншому хостингу задай `DAYFRAME_PUBLIC_URL` як точну адресу походження HTTPS, наприклад `https://your-workspace.example`, без додаткового шляху.
- Секрети зберігай лише в захищених змінних середовища хостингу. Не додавай їх у Git, клієнтський код, чат, localStorage або інсталятор.

Використовуй адресу серверної версії для входу та щоденної роботи. Інтерфейс і сервер навмисно працюють з одного походження: не потрібно послаблювати CORS чи покладатися на сторонні cookie. Кожен браузер отримує окремий серверний сеанс; токени недоступні клієнтському JavaScript.

Шаблон `render.yaml` не означає, що сервіс уже створений. Потрібен твій обліковий запис хостингу; тариф може мати обмеження. Шаблон дозволяє спочатку розмістити застосунок без OAuth. Коли з’явиться адреса сервера, зареєструй застосунки й додай потрібні ідентифікатори та секрети в налаштуваннях середовища цього сервісу. Решта підключень залишаться вимкненими.

## 2. Робочий і особистий Outlook

1. Відкрий [реєстрації застосунків Microsoft Entra](https://entra.microsoft.com/). Створи застосунок із типом облікових записів **Accounts in any organizational directory and personal Microsoft accounts**: це дозволяє підключати і робочий Microsoft 365, і особистий Outlook. Для робочого облікового запису може знадобитися дозвіл адміністратора.
2. Додай дві адреси повернення типу **Web**:
   - `https://YOUR-HOST/api/auth/outlook-work/callback`
   - `https://YOUR-HOST/api/auth/outlook-personal/callback`
3. Додай делегований дозвіл Microsoft Graph **Calendars.Read**. Не додавай права зміни календаря чи читання пошти. Застосунок також запитує `offline_access`, щоб оновлювати токени.
4. Створи секрет клієнта. У захищених налаштуваннях серверного хостингу задай `MICROSOFT_CLIENT_ID` і `MICROSOFT_CLIENT_SECRET`. Для обох типів облікових записів використовуй `MICROSOFT_TENANT_ID=common`; для робочого облікового запису конкретної організації можна задати її ідентифікатор.
5. Перезапусти сервер. У Dayframe відкрий **Налаштування → Твої підключення** й окремо підключи **Outlook · Робочий** та **Outlook · Особистий**.

Використовується одна реєстрація застосунку й один серверний секрет, але два незалежні токени сеансу. Робочий вхід використовує маршрут `organizations` або налаштовану організацію, особистий — `consumers`. Відключення одного облікового запису не відключає другий.

Через Graph `calendarView` завантажується основний календар кожного облікового запису. Обробляються сторінки результатів, скасовані події відкидаються. Час UTC переводиться в часовий пояс пристрою. Вхід захищений перевіркою стану та PKCE. Вибір додаткових календарів поки не реалізований.

Документація Microsoft: [потік коду авторизації](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow), [calendarView](https://learn.microsoft.com/en-us/graph/api/calendar-list-calendarview).

## 3. Календар Google

1. Створи проєкт у [Google Cloud Console](https://console.cloud.google.com/) та ввімкни **Google Calendar API**.
2. Налаштуй екран згоди OAuth. Якщо застосунок у режимі тестування, додай свій обліковий запис до тестових користувачів. Дозволи в цьому режимі можуть спливати за правилами Google.
3. Створи клієнт OAuth типу **Web application**. Зареєструй адресу повернення `https://YOUR-HOST/api/auth/google/callback`.
4. У захищених налаштуваннях серверного хостингу задай `GOOGLE_CLIENT_ID` і `GOOGLE_CLIENT_SECRET`.
5. Перезапусти сервер і натисни **Підключити Календар Google** у Dayframe.

Запитується лише `calendar.events.readonly`. Завантажується основний календар у вибраному періоді, зокрема окремі повторення подій. Підтримується пагінація. Однакові UID події та час її повторення дозволяють прибрати дублікати між календарями; окремі події з однаковими назвами зберігаються. Для подій на весь день дата завершення не включається в подію.

Документація Google: [серверна авторизація OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [events.list](https://developers.google.com/workspace/calendar/api/v3/reference/events/list).

## 4. Slack

1. Створи застосунок у [Slack API apps](https://api.slack.com/apps) для простору, до якого маєш доступ.
2. У **OAuth & Permissions → Redirect URLs** додай `https://YOUR-HOST/api/auth/slack/callback`.
3. У **User Token Scopes** додай `search:read` і `users:read`. Використовується особиста авторизація користувача, а не токен бота. Не додавай дозволи надсилання повідомлень. Організація може вимагати згоди адміністратора.
4. У захищених налаштуваннях хостингу задай `SLACK_CLIENT_ID` і `SLACK_CLIENT_SECRET`.
5. Перезапусти сервер, натисни **Підключити Slack** і вкажи до п’яти каналів у налаштуваннях Dayframe.

Dayframe шукає прямі згадки та повідомлення вибраних каналів за останні 24 години. Показуються до 30 останніх результатів на кожен запит. Якщо результатів більше, застосунок повідомляє про обмеження. Доступність залежить від політики зберігання та прав пошуку Slack. За одне оновлення визначаються імена до 15 авторів.

Це **пошукова стрічка, а не ШІ-огляд чи система припущень про важливість**. Дані не надсилаються до ШІ-сервісів. Жодне повідомлення не стає завданням без натискання «Додати до завдань». Тексти реальних повідомлень відображаються мовою оригіналу.

Документація Slack: [OAuth v2](https://docs.slack.dev/authentication/installing-with-oauth/), [search.messages](https://docs.slack.dev/reference/methods/search.messages/).

## Сеанси та обмеження

- Токени зберігаються в пам’яті сервера. Сеанси діють до восьми годин і зникають після перезапуску, засинання або повторного розгортання сервера. Після цього підключи облікові записи знову.
- Запускай один екземпляр сервера. Для кількох потрібне спільне зашифроване сховище сеансів і координація оновлення токенів.
- Токени оновлення використовуються, якщо сервіс їх надає. Після відмови чи відкликання дозволу потрібна повторна авторизація.
- Відключення видаляє токен поточного сеансу. Щоб відкликати сам дозвіл, видали доступ Dayframe у налаштуваннях відповідного сервісу.
- Особисті завдання та налаштування залишаються в localStorage цього браузера. Повторювані завдання знову відкриваються за наступною датою, коли застосунок відкритий. Фонового процесу немає.
- Дані не синхронізуються між пристроями, вебзастосунком у Dock та різними адресами сайту. Перехід із GitHub Pages на серверний хостинг створює окреме локальне сховище.
- Немає читання пошти, push-сповіщень, погоди, підключень Jira/Confluence, змін у зовнішніх сервісах чи автоматичного фонового опитування Slack. Використовуй «Оновити» або поверни фокус у вікно. Неактивний застосунок не надсилає нагадувань.
- Тести перевіряють авторизацію, межі доступу та перетворення даних на локальних прикладах. Вони не підтверджують дозвіл реального облікового запису.

## Локальна розробка

```sh
npm ci --cache /tmp/dayframe-npm-cache
npm run build
cp .env.example .env
# Заповни власні налаштування безпечно. Не додавай .env у Git.
npm start
```

Для локальної розробки зареєструй `http://localhost:4317/api/auth/outlook-work/callback`, `http://localhost:4317/api/auth/outlook-personal/callback` та відповідні адреси інших сервісів, якщо вони дозволяють локальні адреси. Сервер віддає зібраний інтерфейс на порту 4317.

Для швидкого оновлення інтерфейсу окремо запусти `npm run dev`, задай `DAYFRAME_PUBLIC_URL=http://localhost:5173` та зареєструй адреси повернення з портом 5173. Vite пересилає `/api` на сервер порту 4317. Адреса має точно відповідати походженню сторінки в браузері, щоб працювали повернення OAuth і перевірка походження запитів.
